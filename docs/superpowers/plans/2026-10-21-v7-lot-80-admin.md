# V7 Lot 80 — Admin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `/admin` to V7 **tool mode** (same tokens and fonts, neutral dark panels, 1 px outlines, dense tables, V7 chart palette, no juice) and ship its client-only fixes: sign-out, 429 copy, a 2–8 seat select, consistent loading / empty / error states, Matches and Database paging, keyboard rows, extra match-detail fields and a Chat messages tab. No server, protocol, rule or value change.

**Architecture:**
- Tool mode is a CSS scope, `[data-mode="tool"]` in `ui/tokens.css`. It overrides only the chrome knobs Lot 72 left for it (`--chrome-outline-width`, `--chrome-shadow`, `--chrome-radius(-sm)`, `--chrome-press-y`) plus `--ink` (the outline colour). Every `ui/` primitive inside the scope renders tool chrome **with no code change**; outside it nothing moves.
- `AdminApp` opens the scope on its root. Sheets portal to `document.body`, so every admin `Dialog` passes `dataAttributes={{ 'data-mode': 'tool' }}` to put its panel in the scope.
- Admin-local pieces (status block, table, pager, link bar, field classes) live in `screens/admin/` and replace `design/` imports. Pure route and paging helpers live in `admin/*.ts`.
- Behavior is pinned by happy-dom component tests that drive the real pages against one fake `fetch` (`screens/admin/admin-test-harness.ts`) and shared fixtures (`screens/admin/admin-fixtures.ts`).

**Tech Stack:** React 19 · TypeScript (strict) · Tailwind v4 (`v7-*` utilities from `ui/tokens.css`) · Vitest 4 + `@testing-library/react` / `user-event` on happy-dom (`renderUi`) · `exceljs` exports (unchanged). No new dependency.

## Review Focus

The five input classes most likely to bite, each pinned by a named test:

1. **Sign out, then unlock again, while an old request is still in flight.** A late success must not store the old password again, and a late 401 must not lock the new session. L80-02, `a success that resolves after sign-out does not store the password again` and `a 401 from a request started before sign-out does not lock the next session`.
2. **A page count that shrinks or is zero.** `total = 0` must read 'Page 1 of 1' with both buttons disabled, never 'Page 1 of 0'; Apply after paging must request page 1. L80-06, `zero rows read Page 1 of 1 and disable both buttons` and `Apply after paging requests page=1`.
3. **A deep link to a table that is not allowlisted** (`/admin/data/nope`). The server answers 404: the page shows 'Not found', marks no tab current, and does not crash. L80-10, `a deep link to an unknown table shows Not found and marks no tab current`.
4. **A triage save that fails with 401 or 429.** 401 locks the session; 429 shows the rate-limit copy; the row keeps its status and the marks re-enable. L80-09, `a failed mark leaves the row unchanged, shows an alert and re-enables the marks`.
5. **A phone at 390 px.** Wide tables must scroll inside their region, not the page, and every field must stay at 16 px. Structural tests assert the labelled `ScrollArea` and the `text-v7-input` class (L80-01 `AdminDataTable` test, L80-03 `every filter field uses the 16 px input step`); the computed values are checked in the L80-12 browser gate.
